# 10_status_codes

本目录专门讲清一件事：

同样都是“接口返回错误”，到底什么时候该用 `201 / 202 / 204 / 400 / 404 / 409 / 422 / 429 / 502 / 503 / 504`。

这一章和 `09_self_exception/` 的区别是：

- `09_self_exception/`
  重点讲“异常怎么统一包装”
- `10_status_codes/`
  重点讲“HTTP 状态码应该怎么选”

为了和前面的教程风格保持一致，本章统一使用企业里常见的响应体格式：

```json
{
  "code": 0,
  "message": "成功",
  "data": {}
}
```

错误时同样保持这个结构：

```json
{
  "code": 40901,
  "message": "用户名已存在",
  "data": null
}
```

只有一个例外：

- `204 No Content`
  这个状态码按 HTTP 语义就代表“成功，但没有响应体”，所以这里不要再返回 JSON。

## 文件说明

- `01_crud_status_codes.py`
  演示最常见的资源接口状态码：`201 / 204 / 400 / 404 / 409 / 422`
- `02_async_and_rate_limit.py`
  演示异步任务和基础设施相关状态码：`202 / 429 / 502 / 503 / 504`

## 企业项目里的建议

1. 成功响应尽量统一成 `code + message + data`
2. 资源创建成功用 `201`
3. 删除成功且不需要返回内容时用 `204`
4. 业务规则不满足用 `400`
5. 资源不存在用 `404`
6. 重复提交、唯一键冲突用 `409`
7. 请求格式或字段类型错误用 `422`
8. 限流一定用 `429`，并带 `Retry-After`
9. 上游网关协议错误用 `502`
10. 上游服务不可用用 `503`
11. 上游调用超时用 `504`
