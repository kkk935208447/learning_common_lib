# 教程结构规范

## 目标

把每个库教程设计为可独立学习的课程模块。学习者进入任意一个库目录后，应能看到定位、环境准备、学习路线、示例命令、架构映射、最佳实践、常见陷阱和验证方式。

## 推荐目录

```text
库教程目录/
├── README.md
├── roadmap.md
├── architecture_map.md
├── best_practices.md
├── pitfalls.md
├── examples/
├── templates/
└── smoke/
```

目录不是强制全量创建。小型主题可以裁剪，但必须保留独立学习、独立运行、独立验证的能力，并在 README 中说明裁剪原因。

## 文件职责

`README.md` 负责入口说明：

- 教程定位。
- 适合人群。
- 前置知识。
- 环境要求。
- 安装命令。
- 外部服务准备。
- 目录结构。
- 快速开始。
- 学完后的能力目标。

`roadmap.md` 负责学习路线：

- 按阶段排列，从基础到生产级。
- 每一阶段说明“学什么”“为什么在这里”“关键收获”。
- 每个示例文件给出核心概念和排序理由。
- 不只罗列文件名，要解释学习顺序背后的教学逻辑。
- 当读者熟悉业务流程但不熟悉库 API 时，roadmap 先给“工程使用流程 + API 参数速查概览”，再进入阶段路线。
- API 速查表优先使用 `API/对象 | 常见参数 | 参数说明 | 主要示例`，管理类了解项可用 `API/对象 | 常用参数 | 作用 | 本教程处理方式`。
- 不把官方 API 文档完整搬进 roadmap，只列高频参数、默认影响、生产注意和示例落点。

`architecture_map.md` 负责工程映射：

- 把教程知识点映射到真实项目分层、运行链路或数据流。
- 用文本图、表格或调用链说明组件关系。
- 说明从示例代码演进到生产代码时哪些部分需要替换、封装或下沉。

`best_practices.md` 负责推荐做法：

- 记录稳定推荐的 API、参数、生命周期管理方式。
- 区分开发环境和生产环境建议。
- 说明性能、并发、安全、可观测性、资源清理等工程边界。

`pitfalls.md` 负责反模式与排查：

- 写出常见错误现象。
- 解释根因。
- 给出修复方式。
- 指向对应示例或测试。

`examples/` 负责教学示例：

- 按数字前缀组织阶段，例如 `01_basics/`、`02_request_response/`。
- 示例从最小闭环开始，再进入参数、错误、集成、高阶用法。
- 每个示例尽量独立运行，不依赖其他示例遗留状态。

`templates/` 负责可复用骨架：

- 仅在示例中出现稳定重复模式时创建。
- 面向真实项目复用，不承载教学探索代码。
- README 或模块注释要说明适用边界。

`smoke/` 负责验证：

- 提供一键或分组验证脚本。
- 能自动清理教程专用资源时优先自动清理。
- 不能自动验证外部服务时，写清手动验证命令和风险。

## 教学递进

默认按以下顺序组织：

1. 最小可运行闭环。
2. 核心对象模型和基本调用。
3. 关键参数与配置组合。
4. 输入输出协议和数据结构。
5. 错误、超时、重试、取消、回滚、幂等。
6. 并发、性能、资源管理、安全边界。
7. 与框架或基础设施集成。
8. 企业级模板和生产取舍。
9. 自动化测试或 smoke 验证。

## 每章说明模板

每章或每阶段优先包含：

```markdown
## 阶段 N：主题

**学什么**：说明本阶段的知识点。

**为什么在这里**：说明它和前后阶段的依赖关系。

| 文件 | 核心概念 | 观察重点 |
|------|----------|----------|
| `示例.py` | 关键 API 或模式 | 运行后应看到什么 |

**关键收获**：学习者完成后应具备的能力。
```

## API 型 roadmap 模板

当教程重点是 SDK/API 参数时，优先使用：

```markdown
# 库名 API 全景与学习路线

## 阅读方式与版本要求
## API 全景
### 工程使用流程
### API 参数速查概览
### 按对象分组的 API 说明
## 学习路线总览
## 学习阶段详解
## 模板与后续阅读
```

工程使用流程用短链路展示关键调用顺序，例如连接自检、建模、索引、写入、检索、发布、运维。速查表只做入口索引，细节下沉到示例 docstring 和后续分节。

## 独立性规则

- 每个库目录都要有自己的环境要求和启动命令。
- 不要写“参考另一个教程的环境准备”作为唯一入口。
- 可以链接其他教程补充背景，但当前教程必须保留最小可执行说明。
- 如果需要共享数据库、Redis、消息队列或端口，必须限定命名空间、数据库编号、队列名或临时目录，避免污染其他教程。
- 任何清理命令都必须说明影响范围，禁止无边界清理用户资源。

## 来源记录

新增或大改教程时，在相关文档或验证报告中记录：

- context7 查询的库名、文档主题和用途。
- GitHub 代码搜索的查询词、参考项目或模式用途。
- 未能检索到资料时采用的替代来源和风险。
