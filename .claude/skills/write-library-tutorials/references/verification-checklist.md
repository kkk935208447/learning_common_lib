# 验证清单

## 交付前必须检查

需求字段完整性：

- 目标明确。
- 范围明确。
- 交付物明确。
- 审查要点明确。
- 运行环境和外部服务明确。
- 不做的内容明确。

原始意图覆盖：

- 教师视角明确。
- 从易到难明确。
- 知识参数覆盖充分。
- 高阶用法有独立章节或示例。
- 每个教程模块相互独立。
- 每个 `.py` 示例尽量独立运行。

资料结构：

- README 能作为当前教程入口。
- roadmap 说明学习顺序和排序理由。
- API 型教程的 roadmap 有工程使用流程、API 参数速查概览、示例落点。
- architecture_map 能把知识点映射到真实工程。
- best_practices 说明推荐做法和生产边界。
- pitfalls 说明常见错误、根因和修复方式。
- examples 按阶段编号组织。
- templates 只在确有复用价值时存在。
- smoke 或测试能验证关键路径。

来源记录：

- 记录 context7 查询的库、主题和用途。
- 记录 GitHub 代码搜索的查询词、参考模式和用途。
- 记录无法检索时的替代方法。
- 对不确定 API 不交付确定性描述。

独立性检查：

- 当前教程不依赖另一个教程的 README 才能开始。
- 每个示例文件有运行命令。
- 示例不依赖前序示例遗留状态。
- 示例 docstring 能说明目标、关键 API、重点参数、预期现象和生产提醒。
- 示例输出包含关键中间态，不只打印“成功”。
- 外部服务准备步骤写在当前教程内。
- 清理命令限定教程专用资源。
- 示例运行后有可观察输出。

验证检查：

- 执行可运行示例、测试或 smoke 命令。
- 记录执行命令和结果。
- 工具缺失时记录原因、影响范围和补偿计划。
- 无法验证的内容不得作为已通过交付。
- 连续三次验证失败时停止实现，回到设计和环境假设复盘。

## 本地验证命令模板

按实际教程选择命令：

```bash
uv sync
uv run python examples/阶段目录/示例.py
uv run pytest 路径/测试文件.py -q
uv run python smoke/run_all_examples.py
```

依赖外部服务时补充：

```bash
docker ps
redis-cli -a 密码 ping
mysql -h 主机 -u 用户 -p -e "SELECT 1"
```

命令中涉及密码、密钥、真实地址时，不要把敏感值写入公开文档。教程可以使用本地示例值，并说明生产环境应通过环境变量注入。

`.codex/verification-report.md` 至少包含：

- 交付物：

## 交付物映射

## 评分规则

技术维度评分关注：

- 文档结构清晰度。
- 示例独立性。
- 命令可重复性。
- 测试或 smoke 覆盖。
- 语言和注释规范。
- 与项目风格一致性。

战略维度评分关注：

- 是否匹配用户原始目标。
- 是否符合“标准化 + 生态复用”优先级。
- 是否降低后续维护成本。
- 是否保留教师视角和学习递进。
- 是否准确识别依赖和风险。

综合决策：

- 综合评分大于等于 90 且建议为“通过”：确认通过。
- 综合评分小于 80 且建议为“退回”：确认退回。
- 综合评分 80 到 89 或建议为“需讨论”：仔细审阅后决策。

## 常见退回条件

- 没有验证命令。
- 没有记录外部资料来源。
- 示例必须依赖前一个示例才能运行。
- 文档只有 API 罗列，没有学习顺序。
- 只覆盖基础用法，没有参数、错误、生产边界或高阶用法。
- 说明性文本不是简体中文。
- 清理命令可能影响真实用户数据。
