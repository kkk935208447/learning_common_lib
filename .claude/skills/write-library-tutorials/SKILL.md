# 编写库学习资料

## 核心原则

把输出当作面向学习者的课程资料，而不是零散笔记。每次编写或修改教程前，先理解项目已有风格，再确认库的官方用法，最后组织为可独立运行、可渐进学习、可审查验证的资料。

必须遵守：

- 全部说明性文本、注释、日志、报告使用简体中文。
- 每个库或主题的教程模块相互独立，不能默认读者已经运行过另一个教程模块。
- 每个 `.py` 示例尽量独立运行、独立解释、独立验证。
- 优先复用标准生态、官方 SDK、成熟模式和项目既有结构，不新增自研约定。
- 不确定 API 或版本行为时，先查资料，不凭记忆编写。

## 必读资料

按任务需要读取这些 reference：

- 编写或调整教程目录、学习路线、文档职责时，读取 `references/tutorial-structure.md`。
- 编写或调整 `.py` 示例、测试、模板、运行命令时，读取 `references/example-code-rules.md`。
- 交付前做验证、自审、评分、风险记录时，读取 `references/verification-checklist.md`。

## 工作流程

1. 明确学习对象：库名、版本范围、学习者基础、目标产物、运行环境和外部服务依赖。
2. 扫描当前项目至少 3 个既有教程或示例模式，提炼目录结构、命名习惯、文档层次、测试方式和运行命令。
3. 对编程库、框架、SDK、API 优先使用 context7 查询官方或近似官方文档。
4. 使用 `github.search_code` 查询成熟开源实现，学习真实项目中的最佳实践；只吸收模式，不照搬代码。
5. 先设计学习路线，再写具体文档和示例。路线必须说明“学什么、为什么在这里、学完能做什么”。
6. 如果学习者已熟悉业务流程但不熟悉库本身，优先把路线写成 SDK/API 全景、工程调用链和参数速查，不重复讲业务常识。
7. 从最小可运行示例开始，逐步覆盖核心概念、参数配置、边界条件、错误恢复、性能影响、生产实践和高阶组合。
8. 为每个可运行示例提供明确命令、预期现象、关键中间态输出、外部服务准备步骤和清理边界。
9. 完成后运行可重复验证命令，并按验证清单生成或更新 `.codex/xxxxxxxx-report.md`。

## 教学路线要求

教程默认按以下层次递进：

1. 最小可运行示例：先让学习者跑通完整闭环。
2. 核心概念：解释对象模型、调用链、生命周期、数据流或协议边界。
3. 参数覆盖：列出常用参数、默认值影响、组合方式和推荐配置。
4. 错误与恢复：覆盖异常、超时、重试、取消、幂等、回滚或降级。
5. 生产关注点：覆盖性能、并发、安全、资源清理、可观测性和部署边界。
6. 高阶用法：覆盖组合模式、框架集成、模板封装和真实项目取舍。
7. 验证闭环：提供测试、smoke 脚本或手动可复现实验。

每个知识点至少回答：

- 学什么。
- 为什么现在学。
- 怎么运行。
- 应观察什么。
- 哪些 API 和常见参数在这里出现。
- 生产中怎么用。
- 容易错在哪里。

## 独立性要求

教程模块独立：

- 一个库目录必须包含足够的 README、roadmap 或运行说明，不能依赖另一个库目录的说明才能开始。
- 需要共享基础知识时，只能在当前教程中给出最小必要背景，并链接或引用外部资料作为补充。
- 外部服务依赖必须在当前教程中写清楚，例如 Redis、MySQL、RabbitMQ、OpenAI API、浏览器或本地端口。

示例文件独立：

- `.py` 示例应能从所属教程目录单独运行。
- 示例不能隐式依赖前一个示例遗留的数据库表、Redis key、临时文件、后台 worker 或全局缓存。
- 如果确实需要共享模板或基础设施，只依赖当前教程内的 `templates/`、`support/` 或明确说明的模块。
- 示例必须有可观察输出，避免运行后学习者不知道成功标准。

## 交付要求

根据任务规模交付以下内容：

- `README.md`：定位、适合人群、环境要求、目录结构、快速开始、学习路线概览。
- `roadmap.md`：分阶段学习顺序、每个文件学什么、为什么在这里。
- `architecture_map.md`：知识点到真实工程分层或运行链路的映射。
- `best_practices.md`：推荐做法、参数建议、工程边界。
- `pitfalls.md`：常见错误、反模式、排查方式。
- `examples/`：由浅入深的独立示例。
- `templates/`：生产级可复用骨架，仅在确有复用价值时创建。
- `smoke/` 或测试文件：可重复验证关键示例。

不需要为了形式创建所有文件。若某个库很小，可以裁剪，但必须说明裁剪理由，并保留独立运行和验证能力。
