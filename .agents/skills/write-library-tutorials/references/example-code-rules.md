# 示例代码规范

## 目标

示例 `.py` 文件必须服务教学：读者打开单个文件就能知道它演示什么、依赖什么、如何运行、应看到什么现象，以及生产环境中该如何取舍。

## 文件顶部说明

每个可运行 `.py` 示例顶部优先使用模块级 docstring：

```python
"""
目标: 演示本文件要解决的具体问题
关键 API: 相关库对象、函数、参数或协议
Python 版本: 3.11+
运行命令: uv run python examples/阶段目录/文件名.py
预期现象: 描述终端输出、状态变化或断言结果
生产提醒: 说明生产环境边界、风险或推荐替代方案
"""
```

字段可按场景裁剪，但必须保留目标、运行命令、预期现象。外部服务示例必须补充连接地址、数据库、队列、端口或环境变量。

## 独立运行

默认要求：

- 从所属教程目录运行：`uv run python examples/.../xx.py`。
- 从仓库根目录运行时，README 或文件顶部提供等价命令。
- 不依赖前一个示例已经运行过。
- 不依赖其他示例留下的数据库表、Redis key、文件、端口进程、worker 状态或内存缓存。
- 能自己创建教程专用的最小数据，并在安全范围内清理。

允许依赖：

- Python 标准库。
- 当前项目已声明的依赖。
- 当前教程内明确说明的 `templates/`、`support/` 或基础设施模块。
- README 明确要求启动的外部服务。

不允许：

- 通过隐式导入运行另一个示例的副作用。
- 让示例 A 必须先运行示例 B 才能成功。
- 使用无边界的清理命令影响用户真实数据库、Redis 或文件。
- 为了演示方便隐藏失败或吞掉关键异常。

## 外部服务

依赖 Redis、MySQL、RabbitMQ、HTTP 服务、浏览器或大模型 API 时，示例必须说明：

- 服务用途。
- 默认连接参数。
- 启动或验证命令。
- 教程专用资源命名。
- 清理方式。
- 服务不可用时的预期失败现象。

示例：

```python
"""
目标: 演示 Redis Stream 消费组 pending 消息接管
关键 API: XGROUP、XREADGROUP、XAUTOCLAIM、XACK
运行命令: uv run python examples/04_streams/02_pending_reclaim.py
环境准备: Redis 运行在 localhost:6379，使用教程专用 stream=tutorial:stream:pending
预期现象: 第一次消费者不确认消息，第二次消费者接管并确认
生产提醒: XAUTOCLAIM 判断的是 idle time，不是进程生死
"""
```

## 可观察输出

示例必须让学习者能判断是否成功：

- 打印关键阶段输出。
- 输出输入、状态变化和最终结果。
- 对错误恢复示例打印重试次数、异常类型或降级结果。
- 对性能或并发示例打印耗时、并发数、队列长度或处理顺序。
- 对 Web 示例提供测试文件或请求命令。

避免：

- 只定义函数不运行。
- 运行后无输出。
- 输出过多无关日志。
- 只打印“成功”但不展示关键状态。

## 代码边界

示例应短小聚焦：

- 一个文件只讲一个主要概念。
- 复杂概念拆成多个阶段文件。
- 不为单个示例创建过度抽象。
- 不把生产级模板代码塞进基础示例。
- 变量名、函数名、类名沿用库和项目常见英文标识符。
- 注释用简体中文解释意图和边界，不重复代码逻辑。

## 参数覆盖

参数教学应覆盖：

- 最小必需参数。
- 常用可选参数。
- 默认值的影响。
- 错误配置的现象。
- 生产推荐值。
- 不推荐使用或已过时参数。

参数不要只写成列表。优先用对照表说明“参数、作用、默认行为、生产建议、示例文件”。

## 测试配套

能自动测试的示例优先提供测试：

- FastAPI、纯函数、数据结构转换、错误映射适合配套测试文件。
- 依赖 Redis、MySQL、worker 的示例可以提供 smoke 脚本或手动验证命令。
- 测试名称使用简体中文语义或清晰英文标识符，断言必须验证核心行为。
- 测试数据必须使用教程专用命名，避免污染真实环境。

## 高阶示例

高阶示例必须说明取舍：

- 为什么需要这个模式。
- 它解决基础示例的哪个限制。
- 引入了哪些复杂度。
- 生产中何时使用，何时不使用。
- 如何验证它没有破坏基础语义。
